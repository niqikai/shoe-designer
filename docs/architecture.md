# 架构总览：SDF 场景图 + 杆状晶格

本文是新路线的总览。决策理由见 [docs/adr](adr/) 0001–0006，落地步骤见 [implementation-plan.md](implementation-plan.md)。

## 1. 背景：为什么换路线

此前有两条并行尝试，都没有合并进 master：

| | PR #1（`claude/lattice-shoe-parametric-engine-30b5c7`） | PR #2（`codex/3DPrintedFootwear`） |
|---|---|---|
| 几何表示 | 隐式场 / 体素，TPMS（Gyroid） | B-Rep 精确 CAD（OCCT / build123d） |
| 鞋楦 | Blender 程序化生成 | 真实 STEP 鞋楦 |
| 现状 | 只有规格、12 个 ADR、M0–M7 计划；原型在 `.scratch/`，未提交 | M1 可运行：实体基础鞋 STEP/STL + 实测报告 |
| 主要问题 | TPMS 的壁厚只能事后测量，由此引出合并树颈厚、困粉、悬挂材料、Welt、Cell Properties、局部探测等大量机制；规格 1300 余行，一行代码都还没有 | B-Rep 无法承载大规模晶格；偏置和布尔运算对输入敏感，只针对一只鞋楦调通 |

新路线的核心判断是：**PR #1 的复杂度大多来自"TPMS 的壁厚是涌现出来的"。** 换成杆状晶格后，杆半径就是显式参数，最小壁厚变成参数检查，开放结构也天然好排粉。几何内核仍然用隐式场（这一点 PR #1 是对的），鞋楦则改用真实鞋楦（这一点 PR #2 是对的）。

已确认的前提（2026-10-16）：
- Gyroid 外观不是硬性要求；
- 打印工艺放到最后（M4）再定；
- 鞋面用柔性网眼或仿针织结构，默认仿针织（ADR 0006）；
- 现有鞋楦只用于开发，不商用；自行设计的鞋楦以 STEP 提供，最迟在外部整鞋打样之前到位；
- 打印前缓震档位用估算值，可以接受。

## 2. 总体流程

```
DesignSpec ─► Resolver ─► GeometryGraph（可序列化的 SDF DAG = BuildPlan，带 graph_hash）
                              │
       ┌──────────────────────┼───────────────────────┐
  鞋楦：STEP → 网格 → 窄带 SDF   鞋底：杆状晶格            鞋面：表面图案（网眼/仿针织）
  （尺码变化用 FFD/RBF 变形）    （strut 默认，tpms 可选）
       └──────────────────────┼───────────────────────┘
                              ▼
            块稀疏体素求值（只算材料附近的块）→ 分块 Marching Cubes → 焊接
                              ▼
          检查（通用 hard + 工艺相关 soft，阈值来自 ManufacturingProfile）
                              ▼
                 STL（之后加 3MF）+ report.json + manifest.json
```

| 阶段 | 职责 | 首次出现 |
|---|---|---|
| Last 输入 | 导入 STEP、归一化坐标、三角化、生成窄带 SDF | M0（移植 PR #2 的 loader / normalizer） |
| GeometryGraph | 用节点表示形状和运算；序列化、哈希；任意点确定性求值 | M0 |
| 求值器 | 按块求值、跳过远离表面的空块、分块提取网格并焊接 | M0 |
| 鞋底晶格 | 杆状晶格；M0 按周期公式枚举查询点附近的杆，M1 改为显式节点与杆列表 | M0（均匀 BCC，欧氏坐标） |
| 检查与报告 | 水密、连通、构建体积、杆径下限；报告只写实测结果 | M0 |
| 鞋底完善 | 杆半径渐变、边界节点、实体外底 | M1 |
| 鞋面 | 鞋楦表面参数化 + 仿针织（默认）或网眼图案（ADR 0006） | M2（M0 先用实体薄壳占位） |
| DesignSpec / Resolver | 语义参数 → 可行的 Graph | M3 |
| 打样与选工艺 | 同一套 Graph 输出试块；两种工艺打样、校准 | M4（打印放到最后） |

## 3. 关键设计

### 3.1 GeometryGraph 就是 BuildPlan（ADR 0001）

- 一个有向无环图，节点类型是有限的白名单：基本体、来自鞋楦的采样场、晶格、布尔运算（含平滑并集）、偏置、裁切。
- 规范化 JSON 序列化后计算 `graph_hash`。同一个图、同一个求值分辨率，输出逐位一致。
- 预览、整鞋、Crop、Coupon 都是**同一个图换一个求值区域或分辨率**，不各写一条流水线。

### 3.2 晶格可插拔，默认杆状（ADR 0002）

- `LatticeKind`：`strut`（默认）或 `tpms`（以后再做）。下游只消费 SDF。
- 杆 = 胶囊体，SDF 是到线段距离减去半径；节点处用与顺序无关的指数平滑并集加圆角。平滑并集只会让材料变厚，所以不会把杆径压到下限以下。
- 杆本身的最小壁厚 = 2 × min(杆半径)，在 Graph 构建时检查。但包络裁切、减去腔体仍可能切出薄片，所以网格上另做一项薄片检查（M0 只报告，M1 用边界节点消除裁切后升为 hard）。
- M0 里被包络裁切的杆都并入 1.2 mm 外皮，不留悬空断头；M1 改为在包络表面布点，让杆终止在边界节点上。
- 杆状晶格只用于鞋底。鞋面只有 1–2 mm 厚，装不下三维 Cell。

### 3.2a 鞋面用表面图案（ADR 0006）

- 鞋面是贴着腔体外侧的 1.2–2 mm 薄壳，结构由鞋楦表面参数坐标 (u, v) 上的二维图案决定：网眼（开孔）或仿针织（沿表面走的纱线管体，带法向起伏）。
- 表面参数化：沿后跟中线切开展平。
- 仿针织：线圈在 (u, v) 里设计，再映射成世界坐标里的三维胶囊链求距离，所以实际纱线直径就是参数值，Lipschitz ≤ 1。
- 网眼：把 (u, v) 采样进鞋楦的细栅格窄带，求值时查表；图案场除以参数化与曲率给出的 Lipschitz 上界，最小筋宽按世界坐标下界检查。
- 后跟切缝处用实体加强条盖住，领口一圈实体 Rim，鞋面底边与鞋底外皮熔合。
- 默认用仿针织，网眼为可选方案（实现计划 Q5）。

### 3.3 真实鞋楦 + 变形（ADR 0003）

- 从 PR #2 移植 STEP 导入（含 `FILE_NAME` 头修复）和显式刚体归一化，坐标约定沿用：X 从后跟指向鞋头，Y 为宽度，Z 向上，单位 mm。
- 三角化后用 libigl 的 winding number 求带符号距离，双层采样：0.5 mm 细栅格只存表面附近的窄带，2 mm 粗栅格覆盖外围，求值时三线性插值。
- 不同尺码用少量关键尺寸驱动的平滑变形生成（M3）：先变形鞋楦网格，再重新采样 SDF，不在 SDF 上直接复合变形。不再用 Blender。
- **授权**：现有鞋楦 STEP 的文件头写着 CC BY-NC-ND 4.0，不允许商用（2026-10-16 确认）。它只用于开发阶段：文件和派生几何只留在本地，不入库、不上传、不对外展示，也不发给打样服务商。所以外部整鞋打样必须用自行设计的鞋楦；不含鞋楦几何的独立试块和平板试片不受影响（实现计划 M4）。正式使用的鞋楦由你自行设计；导入接口按通用鞋楦设计，换楦时只需换输入文件和归一化配置。

### 3.4 工艺无关，差异进 ManufacturingProfile（ADR 0004）

- Profile 是带版本的数据文件，包括：最小杆径、最小孔径、构建体积、是否要求排粉孔、输出格式、是否需要支撑。
- 先提供两份占位：`pbf-tpu-generic@0`（粉末床 TPU，MJF/SLS）和 `dls-epu-generic@0`（光固化弹性体）。数值标为"占位，待服务商指南核实"。
- 检查分三类：
  - **构建前参数检查**：杆径不低于 profile 下限、体素 ≤ 最小杆直径 / 4，不满足就不生成网格；
  - **通用 hard**：网格水密、连通分量数、构建体积；
  - **soft**：网格上的薄片、封闭腔、孔径、排粉、支撑；工艺定下前只报告、不拦截。

### 3.5 内存与确定性（ADR 0005）

- 不分配覆盖整鞋包围盒的稠密浮点数组。按固定大小的块（64³ 体素）求值，先用粗粒度的距离下界跳过离表面太远的块。
- 块大小、遍历顺序、合并顺序固定；栅格坐标一律由全局整数索引算出（`origin + i × h`）；并行只在块之间，结果按块序号合并。
- 确定性的范围：同一台机器、同一份 `uv.lock` 下，`shoe.stl` 与 `graph.json` 逐位一致。`report.json`、`manifest.json` 中的耗时、RSS、run_id 不在此列。
- 进程 RSS 有上限（默认 6 GB），超出即中止并报告。开发机为 16 GB 内存。
- 先用自研块稀疏网格。OpenVDB 的 Python 绑定在 macOS arm64 上安装不便，留到 M1 视性能再评估；网格提取是否用现成库由 M0.6a 决定。

## 4. 从两份旧 PR 继承什么

| 来源 | 继承 | 不继承 |
|---|---|---|
| PR #1 | DesignSpec→Resolver→BuildPlan 分层；确定性契约（PR #1 的 ADR 0006）；退出码分类思路；"鞋底只用一种 Cell、层间只改密度"的教训（PR #1 的 ADR 0010）；内存看门狗的纪律 | Blender Shape Source；合并树颈厚；Welt；Cell Properties 与局部探测；1300 行规格的一次性定稿 |
| PR #2 | `last/loader.py`、`last/normalizer.py`、`reporting.py`；"报告只写实测、失败候选不得冒充成功"的原则；产物清单与 run_id | B-Rep 偏置、放样、布尔生成鞋体；只服务于某次精修的分支逻辑 |

两份 PR 暂时保留，由你自行处理（2026-10-16 确认）；本路线的工作不对它们做任何操作。

## 5. 不做的事（至少到 M3 为止）

- 不做 TPMS（接口留着）。
- 不做 Blender 或任何 GUI 依赖。
- 不做 LLM 接口；DesignSpec 先做成人可写的 JSON。
- 不对任何工艺做"可打印"认证；报告里的制造结论一律写 NOT_VERIFIED，直到实物验证。
