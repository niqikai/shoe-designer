# 确定性契约：同环境逐字节一致，跨平台只保证指标等价

同一份 BuildPlan，在同一平台、同一引擎版本（git sha 相同且无未提交改动，内置数据表随之相同）、同一 uv.lock、同一 Blender 完整版本（含 patch 与 build hash）下，Print Mesh 必须逐字节一致；跨平台（如开发用 macOS arm64 与将来的 Linux x86_64 服务器）只保证指标等价：体积 ±0.1%、表面积 ±0.5%、包围盒 ±0.05 mm、连通分量数相同。逐字节跨平台一致在浮点运算下不现实，而同环境逐字节一致是 SaaS 按哈希缓存与补打可追溯的前提。

## Consequences

- BuildPlan 中的数值在写入前按固定精度量化，plan_hash 由固定的规范化序列化计算；同一尺码因运算顺序不同产生的浮点差异不得改变哈希。
- 体素原点（相对引擎坐标系原点偏移半个体素，避免场值恰好为零产生退化面）与分块尺寸是 BuildPlan 中显式、固定的参数；分块尺寸不得随可用内存或线程数自适应。
- 并行只能发生在分块之间，且合并顺序固定。
- 网格简化等第三方步骤必须选用确定性的实现。
- BuildPlan 之外影响几何的量（Feasibility Table 给出的阈值、光滑半径、Island 阈值等）属于引擎版本的一部分，通过 Build Manifest 中数据表的版本与哈希追溯。
- 补打以存档的 BuildPlan 为准；重新解析 DesignSpec 视为用新版引擎重新设计。
- Blender 主次版本不符即拒绝构建；patch 版本不同只警告并记录，此时只保证指标等价。
