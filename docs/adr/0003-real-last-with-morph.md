# 用真实鞋楦，尺码变化靠变形，不用 Blender

鞋楦来自 STEP 或扫描网格，导入和归一化移植 PR #2 的实现（`last/loader.py`、`last/normalizer.py`）。三角化后用 libigl 计算带符号距离，在 0.5 mm 栅格的窄带内采样，作为 GeometryGraph 的叶子节点。不同尺码和楦型由少量关键尺寸（楦长、跖围、跟宽等）驱动的平滑变形（FFD 或 RBF）得到。变形作用在鞋楦网格上，变形后重新采样 SDF；变形参数参与哈希。不在 SDF 上直接复合变形，因为那会破坏 Lipschitz ≤ 1（ADR 0001）。

## Considered Options

- **Blender 程序化控制笼，即 PR #1 的路线**：参数完全可控，但形状真实度要等人工目视签收；引入 Blender 子进程、版本锁定、Shape Bundle 契约和一整类失败码。拒绝。
- **只用一只固定鞋楦**：最简单，但无法覆盖尺码。仅作为 M0 的起点。
- **真实鞋楦 + 变形（采用）**：形状真实度来自实物；变形是平滑映射，不改变拓扑。

## Consequences

- 鞋楦文件和由它派生的几何都只留在本地，不入库、不上传第三方（沿用 PR #2 的 `asset_provenance` 规则）。测试用解析合成鞋楦（圆角体），不依赖授权资产。
- **授权**（2026-10-16 确认）：现有鞋楦文件头为 CC BY-NC-ND 4.0，不允许商用，只用于开发阶段。由它生成的任何几何都只在本地，不对外展示或分发，也不发给打样服务商；需要外部打印的整鞋必须换用自行设计的鞋楦（实现计划 M4、H7）。正式使用的鞋楦由你自行设计；导入与变形接口按通用鞋楦设计，换楦只需换输入文件和归一化配置。
- 依赖 build123d / cadquery-ocp（STEP 读取，LGPL 的 OCCT 内核）和 libigl（MPL-2.0）。OCCT 只在导入阶段使用。
- 鞋楦 SDF 双层采样：0.5 mm 细栅格只存 |d| ≤ 6 mm 的窄带；2 mm 粗栅格覆盖包围盒外扩 30 mm；再往外用到鞋楦包围盒的距离（正值，是真实距离的下界）。
  - 网格只在细栅格窄带内提取，所以图里对鞋楦做的偏置量必须 ≤ 窄带宽度 − 1 mm，构建时检查。
  - 细、粗栅格的切换处有不超过粗栅格误差（约 1 mm）的跳变，只影响跳块判断，由 ADR 0005 的安全系数吸收；Lipschitz 测试只在细栅格窄带内做。
- 采样数组用 `.npy` 存盘，worker 以 `mmap_mode='r'` 打开共享页缓存，避免每个进程复制一份。
- 归一化方向仍是显式配置的刚体变换，不自动推断鞋头方向和左右脚。
