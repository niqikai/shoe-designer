# 块稀疏求值，结果确定且内存有上限

求值器把空间划分成固定大小的块（64³ 体素），先在块中心求 SDF：若 |d(中心)| 大于 k ×（块半对角线 + 一个体素），则整块要么全空、要么全满，不做细采样。安全系数 k 是固定常数（初值 1.5），用来吸收采样场插值和平滑运算带来的 Lipschitz 偏差。只对跨越表面的块逐体素求值并提取网格。块内用自写的 numba Marching Cubes，每个顶点以全局边编号 (i, j, k, axis) 标识；相邻块共享边界上的采样点（每块实际采样 65³），同一条边在两个块里得到同一个编号和同一个坐标，按编号焊接即得水密网格。

## Considered Options

- **整鞋稠密栅格**：0.25 mm 下约 3 亿体素，一个 float32 数组就超过 1 GB，PR #1 的原型曾在 16 GB 机器上耗尽内存。拒绝。
- **OpenVDB**：成熟的稀疏格式，但 PyPI 上没有可用的 Python wheel，`uv` 装不上（M0.6a 实测）。M0 不用；M1 视需要再评估，接口保持可替换。
- **自研块稀疏网格（采用）**：实现量小，内存与表面积成正比。

## Consequences

- 不用 scikit-image 的 `marching_cubes`：它不暴露边编号，只能按浮点坐标焊接。
- **网格提取：自写 numba Marching Cubes，不用现成库**（M0.6a 实测，详见 [m0.6a-meshing.md](../spikes/m0.6a-meshing.md)）。OpenVDB 没有可用的 PyPI wheel，`uv` 装不上，安装不通过。manifold3d `level_set` 的安装、水密流形、确定性、授权都通过，但跨块不通过：它只接受逐点 Python 回调，时间和内存跟包围盒体积成正比（300 × 120 × 150 mm 的盒子里只放一个球，edgeLength 0.25 mm 要 77.5 s、4.28 GB，同一栅格的 float32 稠密数组只有 1.29 GB）；分块调用时每块在包围盒边界补盖子，加重叠区再裁剪后，也只有体素能被二进制精确表示（1.0、0.25 mm）时才能逐位拼回，0.3 mm 时顶点相差约 3e-14 mm，不能按精确坐标焊接。块划分、跳块、全局整数坐标和按全局边编号焊接的规则不变；manifold3d 只作可选的第二意见，在子进程里运行（它全程持有 GIL，会饿死看门狗线程），水密、流形、欧拉示性数由自写的 numba 检查负责（M0.6）。
- 采样值恰为 0 时按"外部"处理，此时顶点落在栅格点上，多条边会生成同一坐标的顶点；焊接后再按坐标合并一次，并删除退化三角形。这一步也是确定性的。M0.6 实现时的三点补充：
  - |v| < h/1024 的采样值视同 0。否则倾斜平面经过栅格点时，求值的舍入噪声（约 1e-16、符号随机）会让相邻两个栅格点和它们之间的边中点各出一个顶点，形成零面积三角形；视同 0 后它就是精确为 0 的平面。表面移动不到 h/1024。
  - 只合并由零长度边相连的同坐标顶点，每组合并后检查周围：没塌成一个顶点、相邻边不是恰好两个反向三角形、顶点不止一扇、出现两个三角形共用三个顶点、或出现零面积三角形，这一组就不合并，改为把它的顶点沿各自的边移离栅格点 max(h/1024, 4 个 float32 ulp)，恢复 Marching Cubes 本身的流形拓扑；反复检查直到没有被拒的组。合并是边坍缩，距离场产生的情形（平面过栅格点：一个点、一条边或一个三角形）总能通过；任意符号分布则不一定（随机零值场里实测到一条边四个三角形、一个顶点两扇），这一步保证结果仍是闭合流形且没有重合顶点。
  - 顶点坐标在提取时就舍入到 float32（STL 的精度），合并与检查都针对实际写出的坐标。
  歧义面只看四个角点的符号：内部角点在歧义面上相连（详见 `src/shoegen/mesh/tables.py`）。
- 块大小、体素原点、块遍历顺序、合并顺序全部固定。栅格坐标一律由全局整数索引计算（`origin + i × h`），不用 `linspace` 或块内局部偏移相加，否则共享边界上的值不能逐位相同。实现里 `origin` 取世界原点 0，`i` 是相对世界原点的全局整数索引，坐标就是一次乘法 `float64(i) × h`；区域的最小角只决定从哪个索引开始分块（`g0 = floor(region_min / h)`），不进入坐标计算，所以同一个点在不同区域、不同分块下坐标也逐位相同（M0.5，`tests/test_evaluate_blocks.py::test_different_regions_share_global_samples`）。并行只在块之间，worker 数默认 4、不随可用内存变化。结果按块序号合并。
- 同一点在不同分块下求值必须逐位一致：每种节点只有一条 numba 实现路径，批量求值只是循环调用同一个内核；禁用 `fastmath` 与 `parallel=True`。确定性只承诺在同一台机器、同一份 `uv.lock` 下成立。
- 这一跳块判据依赖 ADR 0001 要求的 Lipschitz ≤ 1。采样场（鞋楦）在窄带外不能被截断成常数，否则远处的块无法被正确跳过；见 ADR 0003 的双层采样。
- 采样场在粗栅格外改用"到包围盒的距离"（下界），切换处向下跳变，在粗栅格角上可达 R(√3 − 1)，超过 k 留出的余量（0.25 mm 体素下为 7.3 mm）。k 不负责吸收这一跳变：远场里 |d| ≥ 粗栅格超出包围盒的距离 m，且符号取自粗栅格，只要 m 大于施加在该采样场上的累计偏置，就不会产生零交叉；块中心落在远场时下界只会让跳块更少。`shoegen.evaluate` 在规划时检查 m > 偏置量，不满足以退出码 3 拒绝（M0.5，测试见 `tests/test_evaluate_blocks.py`）。k 只需吸收细/粗切换（≤ 粗栅格误差）和三线性插值的偏差。`Extrude2D` 的二维栅格在栅格外也改用"到轮廓包围盒的距离"，结构相同；M0 评审补上了同样的检查：二维栅格超出轮廓包围盒的距离必须大于节点自身的正 `offset` 加上它上方的累计偏置，否则退出码 3（`check_far_field_margins`，测试 `test_extrude2d_far_field_margin_must_exceed_offset_reach`）。
- 跳块的正确性有专门的测试：对同一图分别用跳块和不跳块求值，网格经规范化排序（顶点按坐标字典序，三角形按顶点编号）后必须完全相同。
- RSS 看门狗是主进程里的 Python 线程：主进程在长时间持有 GIL 的调用里（例如不带 `nogil` 的 numba 内核、scipy 的 Delaunay、libigl 的 AABB 查询）时它采不到样，可能超限而不被发现（M0.6a 实测）。M0 的对策：项目自己的 numba 内核都用 `nogil=True`（M0 评审把 `last/projection.py` 里漏掉的三个也补上了），worker 池的内存在主进程等待时能被采到；`report.json`/`manifest.json` 另记内核给出的 `ru_maxrss`（主进程、最大的子进程），不依赖这个线程。进程外的监督进程不在 M0 范围内。
- RSS 上限（默认 6 GB，CLI 可调）统计主进程及所有 worker 的总和，所以超限时也要终止同一范围：写失败报告 → 终止并回收全部子进程（先 SIGTERM，2 s 后 SIGKILL）→ 父进程 `os._exit(6)`（后台线程里的 `sys.exit` 无法终止进程）。只退出父进程时，正在计算的 worker 会成为孤儿继续占内存（已用单 worker 的 `ProcessPoolExecutor` 复现）。父进程被强杀时由 worker 自己检查父进程是否变化并退出，见实现计划 M0.1。
- 确定性的范围是 `shoe.stl` 与 `graph.json`：不含时间戳，JSON 键排序，没有随机数。`report.json`、`manifest.json` 中的耗时、RSS、run_id 不在此列。
