## Core/shell construction: viable with explicit semantics

Let B be the accepted base mesh, L the selected accepted lattice, and D the saved M2 domain field. Use `C = contour(D + overlap_field_mm < 0)`, `S = B - C`, `A = (S union L) intersect B`, then subtract accepted upper-hole cutters H: `F = A - H`.

The current D grid is float32, XYZ `(714,275,85)`, spacing 0.4 mm, origin `[-4.054067744186359,-54.67644035380791,-16.40000000000002]`. Direct read of the saved field found min=-5.2946047783, max=0.4000000060, 2590300 negative nodes, and 1741833 nodes below -0.8. Thus the proposed core is nonempty at the node level. This does not yet establish its extracted volume or topology.

`domain.py` constructs D as minimum signed distances to conservative interior balls, with positive samples initially capped at one grid spacing; adaptive completion extends signed balls into the positive ring. It is not the signed distance to the exact CAD sole boundary, nor generally the exact signed distance to the union boundary. `D=-0.8` is an inset **field level**, not a claim of a uniform 0.8 mm wall. The M2 certificate already reserves 2.0 mm clearance plus one cell diagonal (0.692820323 mm) and numerical reserve from CAD/cavity/window boundaries. Actual retained solid exterior is consequently substantially thicker in some regions and follows conservative ball coverage rather than a fixed shell offset.

The selected lattice's intended cap is at D approximately -0.0004 mm, subject to its recorded extraction level. The retained band from D=-0.8 to the cap supplies volume overlap instead of relying on coincident surfaces. However, aggregate overlap alone cannot prove all lattice pieces connect: a disconnected lattice component can lie wholly inside C. All fragments must be retained and measured; fail final single-physical-body validation instead of deleting islands.

The appropriate parameter name is `overlap_field_mm`, with `definition: "offset of saved conservative domain field"`. Require finite positive value, greater than the recorded actual cap inset plus numerical guard, and less than `-D.min()`; additionally require nonempty extracted core and nonzero overlap/added lattice/remaining void. For this first template retain the proposed 0.8 mm as an experimental fixed default (two samples), not a manufacturing threshold. Do not assert support for the whole scalar range from these algebraic bounds. Extract from the exact saved grid with the saved axis/origin/spacing; do not resample D or reconstruct it from the current regression domain.

Marching Cubes must preserve every component and report actual contour level, active cells, memory bound, triangle counts and precision. The existing lattice extractor has dimensionless Gyroid metadata and a bounded inward contour ladder; blindly applying it to D+0.8 would mislabel physical offsets and could silently change the core. Either provide an explicitly field-unit-aware core extraction contract or fail with the actual degeneracy evidence. Any bounded retry must record its resulting physical core threshold before use.

Thin toe areas without D<-0.8 remain solid by construction. This is a conservative M3 transition, but a global `added_lattice_material > 0` check alone could mask loss of the intended forefoot lattice: report the same volumes by heel/midfoot/forefoot/toe bins and identify where C is absent. Preserve the frozen lattice identity while distinguishing its role inside the assembled core from its original standalone appearance. Show cutaway/section previews because an opaque external render cannot demonstrate internal lattice retention.

## Independent assembly acceptance

Before Manifold construction, load STL records without `process=True`. STL is triangle soup, so an explicit exact-coordinate index reconstruction is necessary; record it as lossless indexing with identical triangle coordinates, not tolerance welding. Reject nonfinite coordinates, collapsed/duplicate faces, nonmanifold edge incidence, inconsistent directed-edge orientation, non-cyclic vertex links, invalid shell nesting and unsupported self-intersections. No face removal, fill, smoothing, normal repair, tolerance merge or island deletion is permitted. Manifold status is a second check, not the input validator. Validate every Boolean result and exported result independently as well.

The current `validation.geometry.validate_mesh` is unsuitable without a new M3 policy: Path input invokes `process=True`, expects one face-adjacency component, and by default enforces Euler=2. Internal void shells and deliberate perforations invalidate those M1 assumptions. Compute connected boundary shells explicitly, signed volume per shell, containment/nesting, and physical material components. Require exactly one positive material body, while allowing correctly nested negatively oriented void boundary shells. A positive island nested inside a void is a second physical body and must fail. Never flip each boundary shell to positive volume: that fills the meaning of internal voids.

Report these measured set quantities with declared numerical tolerances, rather than merely Boolean completion:

* `core_inside_base_volume`, `core_outside_base_volume`, and `core_volume`. Core extraction is protected by the original CAD certificate, but the frozen faceted B boundary is a different representation; measure the relation to B too.
* `lattice_shell_overlap_volume = volume(L intersect S)`, with component-level participation.
* `added_lattice_material = volume((L intersect B) - S)`, equivalently added retained material within C. Compare against an explicit numerical volume floor; do not use an unqualified floating `>0`.
* `remaining_void = volume(B - A)`, before upper holes are subtracted. Require positive above the floor and verify its support lies in C. If this is measured only after perforation, a solid-filled sole could pass because the upper holes supply the missing volume.
* Set identities `A subset B`, `(B-A) subset C`, and `(L intersect B) subset A`; record both symmetric residual volumes and available directed surface-distance evidence. After holes, `B-F` must lie in `C union H`, while protected base surface regions retain their original coordinates within export tolerance. Bounding-box equality alone cannot prove silhouette preservation.
* Existing CAD last/cavity/opening constraints remain binding. A subtractive F subset B cannot add material into the frozen cavity, but mesh-to-CAD approximation error must retain M1's scope and tolerances. Independent new containment probes should target Boolean interfaces and the footprint of each hole, not reuse generator success flags.

Basic self-intersection detection should use spatially filtered nonadjacent triangle pairs, with adjacency/coplanarity/contact policy explicitly stated. If unavailable or bounded before full coverage, mark `NOT_VERIFIED`, never infer a full check from watertightness or successful Manifold import. Numerical volume and area floors must be separate from manufacturing minimum-feature rules and established with scale-sensitive negative cases.

## Robust hex-hole placement

Resolve fractions against the frozen normalized last's X range, not base bounding-box length: that last is approximately X=0..276.658443 mm, so 0.67..0.82 maps to X≈185.361..226.860 mm. The outer/base extends past those endpoints. Treat that range as candidate generation bounds, then apply actual geometry rejection. For a conservative first pilot use central Y approximately -20..20 mm and require `normal_z >= 0.8`; expose these as template controls, not guarantees about arbitrary lasts.

1. Generate a deterministic staggered grid in the chosen XY candidate window. Cast downward from above the actual base bounding box. Use the top retained base hit, require a corresponding native outer hit, and retrieve the actual trimmed face normal. Reject edge/tangent/duplicate/ambiguous hits. Validate normal sign using material-side classifications or oriented intersections; the cavity outward normal is opposite the shoe material normal on the inner wall.
2. Form a tangent frame by projecting global X onto the normal plane and normalizing; set the other tangent to `n cross u`. Use an explicitly defined `hole_flat_to_flat_mm` (circumradius = flat-to-flat/sqrt(3)); never confuse it with circumdiameter. A 4 mm flat-to-flat, 8 mm initial center pitch is a reasonable experimental pilot **candidate**, with final web distances validated in 3D. Planar grid separation does not certify web width when neighboring frames tilt.
3. Intersect an inward line along -n with base and cavity. Require exactly one initial upper material span, followed by a cavity interval with enough depth for a short cap. Construct a prism from slightly outside the outer surface to slightly past the cavity entry; never use a shoe-height prism. The nominal 2.5 mm thickness is a search hint, not the cut depth. Compute the actual maximum crossing depth over the footprint and a bounded overshoot, e.g. 0.3 mm as an experimental numerical/template margin; reject if next material is approached.
4. Repeat checks at center, six vertices, and six edge midpoints, adapting along edges where curvature varies. Require all far ends inside the actual cavity and all near ends outside outer. Center-only success misses a blind partial hole or damage at one hex corner. Finite probes should be labeled sampled; final cutter-volume checks provide the geometric exclusion certificate.
5. Validate the complete cutter against protected sets before accepting it. The complete prism must avoid `opening.step` plus configured collar keepout, the original sole/core region plus connection keepout, and the footbed. Use real CAD distance/Boolean geometry, not only `z > constant`. The union of accepted cutters must leave a configured web distance to all neighboring cutters and the actual entry rim. A sufficient conservative collar test for this restricted pilot is requiring the whole cutter X minimum exceed opening's maximum X plus collar margin; the general implementation should use actual opening distance. Record each rejection rather than silently reducing density.
6. Subtract accepted cutters from A, then independently prove each chosen center has an exterior-to-cavity void route, the actual hole footprints stay in the declared region, zero cutter removal occurs in protected material, and final one-body topology holds. Record requested versus accepted counts and removed volume per hole. A parameter test must show actual changed hole geometry, not merely changed JSON.

Proposed pattern fields: `type="hex"`, `hole_flat_to_flat_mm`, `pitch_mm`, `region.last_x_fraction_range`, `region.y_range_mm`, `region.minimum_outward_normal_z`, `collar_keepout_mm`, `sole_connection_keepout_mm`, `minimum_web_mm`, `cavity_overshoot_mm`, `maximum_cut_depth_mm`, `max_holes`, and `placement_algorithm_version`. Enforce finite ordered bounds and positive sizes, and geometry-derived constraints after schema validation. Current `PatternParameters` accepts only `none`; extending it belongs after M2's source-bound runs are finished.

Per-hole evidence should contain candidate grid index, accepted/rejected reason, actual base and outer face IDs plus input SHA, center, normal, frame, dimensions, material/cavity intervals for every probe, maximum cut depth, collar/sole/neighbor distances, cutter SHA or vertex data, removed volume, and final opening verification. Face IDs are useful only with immutable source hashes.

## Precision and export

Manifold3D 3.5.4 exposes `Mesh64` and `to_mesh64`; use both ends to retain computed double precision. This does not undo the float32 quantization already present in frozen input STLs. At X≈280 mm a binary32 ULP is 0.000030517578125 mm, with half-ULP rounding about 0.0000152587890625 mm. Boolean intersection slivers can be smaller than that even when the design features are millimetres wide, so native valid topology does not imply valid binary STL roundtrip.

Preflight each candidate export precision using quantized vertices while retaining all faces and vertex identities. Check coordinate collisions, zero/tiny triangle areas, orientation reversals, edge and vertex links, signed shells and physical body count, then test the actual reimport. A tiny area can be a valid narrow triangle rather than a hole; its rejection policy must be recorded and cannot be silently solved by face removal. If binary STL quantization fails, emit explicit ASCII STL with 17 significant digits and validate using a parser that actually preserves float64. Do not assume a generic STL reader does so; inspect its ASCII implementation or compare exact reconstructed coordinates.

Standard 3MF XML decimal vertices can carry the 17-digit coordinates. Use `unit="millimeter"`, one triangle-mesh object for the physical shoe, standard core mesh elements, explicit build identity, and ordinary package content-types/relationships. A strict decimal XML readback plus an independent installed 3MF reader should check units, coordinate orientation, index topology, bounds, volume and shell/body interpretation. The current trimesh 3MF writer uses Python coordinate formatting, but precision and the selected reader's actual behavior still require roundtrip verification.

**Standard GLB does not preserve double-precision POSITION data.** The installed trimesh writer explicitly casts positions to float32 and writes glTF component type 5126 (`exchange/gltf/__init__.py`, lines 816–822). Keep it as a declared preview, with a separate quantization report. Apply mm-to-m scaling and a documented right-handed Z-up to Y-up transform, e.g. `(x,y,z) -> (x,z,-y)*0.001`, then invert that transform for engineering roundtrip comparison. Do not include GLB in a claim of double-precision manufacturing identity. If preview quantization creates invalid triangles, report and address it explicitly; never silently repair the authoritative mesh or lower manufacturing acceptance.

Manifest fields should include immutable M1/M2 acceptance bindings, CAD support hashes, domain SHA/grid metadata, M3 configuration SHA, code/dependency versions including Manifold3D, actual Boolean ordering, contour levels, `repair_applied=false`, `components_removed=0`, each export encoding/coordinate precision/units/transform, SHA/bytes/time, and individual reimport validation report paths. Persist native float64 vertices and integer faces in a small-protocol NPZ sidecar as a diagnostic numerical reference, without pretending it is a replacement for required STL/3MF files.

## Blocking distinctions for implementation and acceptance

The first execution blocker is the final M2 READY gate. A later failure of positive body count, strict input or roundtrip topology, retention volumes, protected-region checks, or required hole proof is an M3 geometry failure and must retain diagnostics.

This proposed closed core-shell construction **encloses the remaining lattice voids**: C lies strictly inside B, and S preserves the whole surrounding skin. Upper vamp holes do not intersect C and therefore do not provide an escape path for lattice powder. That is a specific design consequence, not just absence of a measurement. Geometry POC can record enclosed void shells and keep powder removal unverified, but cannot claim a powder-removable SLS shoe. If accessible powder removal is required for M3 acceptance, a dedicated drain/access design is a separate unresolved design change, potentially affecting the frozen exterior. Do not add such ports opportunistically or assume the shoe mouth drains the sole.

The current manufacturing JSON has null wall/feature/clearance thresholds, no configured build volume and no powder-removal rule. Step 6 therefore still requires implementation of rule loading and explicit `NOT_VERIFIED` outcomes, plus reporting unavailable configuration. Global minimum wall/feature, global self-intersections if not fully checked, SLS/TPU qualification, powder-removal feasibility and physical fit/printing must remain distinct from geometry PASS. No raw field threshold, sampled 2.5 mm wall, or positive volume substitutes for these checks.

Meaningful negative cases for the new M3 validator are: two bodies touching at one vertex; enclosed correctly oriented negative void shell; positive island inside that void; intentional upper perforation with non-Euler-2 surface; open mesh; duplicate/inverted triangle; cutter crossing footbed or collar; center-open but corner-blind hole; filled core with upper holes still present; disconnected interior lattice island; and float64-valid triangles that collapse in float32. These target failure modes of the proposed design and export pipeline.

## Follow-up: internal footbed access ports

The parent task proposes explicit short footbed ports as an internal structural design change: radius 2 mm as an experimental template parameter, starting inside actual sole void and ending in the original cavity, with no outsole/sidewall penetration. This is geometrically plausible and preserves exterior silhouette. It deliberately changes the interior footbed and must be reported as such; it is not unchanged fit-support geometry. The closed-void conclusion above applies to the initial construction before these ports.

Use the actual pre-port free space `V = B - A = (B intersect C) - L`, not unconditionally `C-L`: C is a sampled representation, while B is the frozen faceted base, and any outside-base component must not be treated as powder trapped in shoe material. Decompose V into **positive physical void volumes**, accounting for any nested boundary shells. Do not confuse `mesh.split()` boundary surfaces with connected open volume. Assign stable component IDs, volume, bounds, representative interior points, and original triangulation hashes before generating ports. Keep every component and every failed access attempt.

The 12-line probe budget is already exhausted. The four measured stations provide exact cavity-floor and bottom intersections and therefore useful initial XY seeds, but they do not identify which Gyroid void lies below or verify a complete radius-2 footprint. A component can project to one XY location while material separates it from the floor. Candidate placement in implementation must use actual V component geometry and fresh bounded native lines or precise mesh intervals. No further native rays were run for this review.

For each V component, search XY over its projected interior, prioritized by distance from its lateral boundary and the outer sole skin. At a candidate XY, order full vertical material/void/cavity intervals. Identify the first actual cavity floor above that component, not the cavity roof and not a min-Z bounding box. Construct a finite drill P from a point inside the selected void interval to a point inside cavity beyond the actual floor. The upper overshoot must cover the highest floor crossing over the **whole disk**, not only center floor+2 mm. Its lower cap must stay above the actual outsole everywhere over the disk; avoid both outer sidewall and toe rise. Do not extend the drill to a universal Z minimum.

The tube may cross intervening Gyroid walls. This is intentional material subtraction but changes local lattice connectivity and support. Re-run final physical material body count and lattice-retention checks after all ports; a perfectly connected free space can coexist with detached solid fragments. Record volume removed from footbed and from lattice separately, remaining minimum sampled ligament/web near ports, and failed protected-region/strength checks. A row of closely spaced ports must not sever the footbed or collapse into a long slot without being reported.

Build a connection graph whose nodes are each original void component, the actual cavity, and every port. An edge requires an independently measured **positive-volume intersection above the declared numerical floor**, not a shared vertex/edge/face, bbox intersection, zero signed distance, or mere composed-object count. Both `volume(P intersect V_i)` and `volume(P intersect cavity)` are needed for a direct port; one port may connect multiple V components, and a connected graph can justify fewer ports. Include the entire port extending into the existing cavity in this connectivity computation. If the port is first clipped only to solid B, it ends at the cavity boundary and the intersection volume with cavity becomes zero even though the physical opening is valid; keep cutter and removed-material geometries distinct.

Require every original V_i to survive as a subset of final free space and to reach the cavity node. Do not validate only the union that happened to remain after an operation which may drop a small component. In addition to the graph, evaluate `W = V union all(P) union cavity` and require one positive physical free-space body with valid shell nesting. Compare each original V_i against W for loss and confirm the same result after actual export. A union's one-object/one-shell status alone can mistake point contact for a usable route, so the positive-volume edge witnesses are still required.

Positive overlap can itself be arbitrarily small. A radius-2 cutter grazing a void creates a near-zero neck even with positive volume. For a robust geometric connection require a measured overlap cross-section and a finite interior witness (e.g. an explicitly bounded ball or section disk contained in both port and void), with minimum radius/area set as a **numerical/template acceptance control**. Store the actual bottleneck estimate and its method/coverage; a port's nominal 4 mm diameter is not evidence that the complete access route is 4 mm wide. The same applies where the drill meets the curved footbed/cavity. Quantization must not close that overlap on STL/3MF readback.

Whole-prism/cylinder distance or Boolean checks must prove the ports avoid protected exterior skin, outsole, sidewall, upper, and collar; centerline or endpoint checks are insufficient. Keepouts should be stated as experimental design controls and evaluated on the actual CAD/mesh geometry. For the pilot stations, centerline cavity floor-to-outsole depth is approximately 15.034,14.512,14.433,13.219 mm, but those centerline values do not certify the whole 4 mm diameter port or a chosen void below it.

Proposed additional interface: `assembly.void_access.enabled`, `port_radius_mm`, `cavity_overshoot_mm`, `minimum_exterior_skin_keepout_mm`, `minimum_port_web_mm`, `minimum_overlap_volume_mm3`, `minimum_connection_witness_radius_mm`, `max_port_count`, `candidate_budget_per_component`, `placement_version`. Geometry-derived range checks must reject an unsatisfied component instead of shrinking, filling, dropping, or ignoring it. Report `original_void_component_count`, per-component `access_status`, connection graph with measured witnesses, `sealed_component_count_after_ports`, actual port endpoints/dimensions, interior-footbed area/volume changed, total lattice removed, final material body count, and precision-specific path survival.

A successful geometric path permits `void_to_cavity_connectivity=PASS` with the declared numerical method. It still does not establish powder flow, minimum factory drain diameter, powder evacuation from long/tortuous Gyroid passages, cleaning tool access, fatigue strength, support comfort, or printing qualification. Keep those checks `NOT_VERIFIED` until their rules and evidence exist. Do not label all powder-removal requirements PASS merely because W is connected.
