# ============================================================
# 10. Step 3 — Gyroid 隐式场
# ============================================================

主要技术：

NumPy
SciPy


目标：

在鞋底设计域内生成 Gyroid 隐式晶格。


Gyroid 函数：

G(x,y,z) =
sin(x)cos(y)
+
sin(y)cos(z)
+
sin(z)cos(x)


根据 lattice_period 缩放坐标。

例如：

k = 2π / period

计算：

G(kx, ky, kz)


使用：

abs(G) - threshold

表示基础壁状 Gyroid 隐式场。


注意：

threshold 是无量纲参数。

它不是毫米单位的真实壁厚。

如果需要实际壁厚控制，
必须另外建立标定或几何测量方法。


必须支持：

- 晶格周期
- 隐式阈值
- 采样间距
- 鞋底设计域裁剪
- 可配置计算边界


晶格不能填充鞋腔。

晶格必须被限制在鞋底设计域内。


输出：

Gyroid 隐式场数据
场参数
计算元数据


必须检查：

- 标量场包含有效零等值面
- 参数修改会改变场
- 设计域裁剪正确
- 内存使用可控


对三维网格分辨率设定上限。

记录：

运行时间
体素数量
峰值内存估计
采样精度


如果模型较大，
允许采用分块处理或局部计算。

不得无控制地创建超大 NumPy 数组。

任务 A：鞋面透气网格

实现一种基础鞋面开孔结构。

建议：

Hexagonal Pattern

需要支持：

- 网孔尺寸
- 网孔分布
- 鞋面结构厚度

任务 B：鞋底晶格融合

将 Gyroid 晶格限制在鞋底设计域。

与外底、鞋面连接区融合。

- 外壳与晶格连接
- 晶格与实体过渡
- 多余网格裁剪
- 开放边界
- 孤立结构


任务 C：整鞋融合

整合：

鞋面网格
+

+

+

# 13. Step 6 — 几何与制造规则检查
# ============================================================

主要技术：

NumPy
自定义 Python DFM Rules


建立：

ValidationEngine


至少包含：

1. 水密性检查
2. 非流形问题检查
3. 连通组件数量检查
4. 模型尺寸检查
5. 模型体积检查
6. 法向一致性检查
7. 基础自相交检测
8. 鞋腔完整性检查
9. 鞋楦与鞋腔空间关系检查
10. 最小壁厚检查
11. 基础晶格特征尺寸检查
12. 制造工艺规则检查


必须区分：

Geometry Validation

和

Manufacturing Validation


Geometry Validation：

验证几何结构是否满足
已实现的计算规则。

Manufacturing Validation：

验证是否满足指定打印工艺、
材料和设备的约束。


制造规则从独立 JSON 读取：

manufacturing_rules.json


例如需要定义：

- process
- material
- build_volume
- minimum_feature_size
- minimum_wall_thickness
- powder_removal_requirements

具体数值不能任意作为行业通用标准。

如果尚未取得目标工厂规范，
必须将规则标记为：

EXPERIMENTAL


注意：

Trimesh 不自带完整的鞋类制造校验功能。

对于无法可靠实现的检测，
必须明确标记为：

NOT_VERIFIED


检查状态：

PASS
WARNING
FAIL
NOT_VERIFIED


规则：

PASS 只能表示当前已执行检查通过。

不能代表全部制造性能已经验证。

任何未执行的关键制造检查，
必须在最终报告中明确列出。

不得将未知状态自动转换为 PASS。


输出：

validation_report.json


报告至少包含：

检查名称
检查状态
检查值
阈值
规则来源
错误信息
检查时间
整体状态


必须编写负面测试。

例如：

- 开放网格
- 非流形网格
- 超出尺寸限制
- 非法参数
- 孤立组件

确保检查器确实能识别问题。

python -m shoe_poc run \
